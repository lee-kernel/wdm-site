---
title: 工作空间与 MCP 接入
description: 维护个人工作空间配置，按需授权可信 Agent 使用业务能力。
---

Mori 为每个账号提供个人工作空间。你可以把工作目标、背景、偏好、标准和协作边界写入空间配置，并通过 MCP 将明确授权的内容与工具交给兼容客户端。

## 1. 编写空间配置

进入 **空间管理 → 空间配置**，编辑 `AGENTS.md` 并保存。页面提供编写指南和默认模板；恢复模板只改变编辑中的草稿，仍需点击保存。

先写 Agent 完成工作必需的事实和边界，再逐步补充细节。保存后的配置会在外部 Agent **下次读取**时生效，已读取内容的会话不会自动更新。

## 2. 创建 MCP 授权

1. 进入 **连接与集成 → MCP 授权**，创建一个便于识别的授权。
2. 选择有效期及所需的操作权限。若希望客户端读取空间配置，选择 `workspace.read`；知识、避坑经验、提示词、脚本、标签、工作报告和工作流各有独立权限。读取、创建、编辑、删除和运行也分别授权。
3. 创建后可选择 **复制接入提示词**，也可按页面给出的地址手动配置 Streamable HTTP 和 Bearer 认证。令牌明文只显示一次，请存入客户端受保护的位置。丢失时撤销旧授权并重新创建。
4. 连接后检查工具列表；若已授予 `workspace.read`，调用 `get_workspace_config`，核对返回的空间内容。具备该权限时，接入提示词还会提供 `mori-workspace` Skill 的地址，供支持 Skill 的客户端使用。

令牌只能委托当前账号用户组已有且允许委托的权限。用户组降权会即时收回相应访问；以后新增的权限不会自动加入旧令牌。客户端工具列表反映当前有效权限，修改授权后可重新加载。

## 3. 使用业务工具

按需授权后，Agent 可查询本人已发布的[知识档案](../knowledge/)、避坑经验、提示词、脚本、报告和工作流。知识草稿不会通过 `knowledge.read` 搜索或详情暴露；`knowledge.edit` 只允许编辑草稿，不自动包含读取已发布知识的权限。MCP 不提供直接运行脚本的工具。

创建操作使用幂等键，编辑和删除会检查当前版本。删除与运行工作流还要求客户端在本次操作前取得你的明确确认；令牌权限不能代替这次确认。工作流运行可能产生真实执行或通知，请先检查配置与副作用。

多个账号应各自使用独立令牌。客户端能否同时管理同地址的多条连接、是否主动选择工具，取决于客户端实现，配置后逐一验证。

## 常见问题

- **看不到某个权限：** 请管理员检查当前用户组的操作权限；菜单可见性与操作授权分别管理。
- **连接后没有预期工具：** 检查令牌选择的权限、当前用户组权限，并重新加载客户端工具列表。
- **读不到刚保存的配置：** 让客户端重新调用 `get_workspace_config`；先前读取的会话不会自动刷新。
- **升级后旧令牌连接失败：** 当前版本使用 `mori_mcp_` 前缀。若客户端仍使用旧版令牌，请在 Mori 新建授权，并更新客户端中保存的令牌。
- **令牌泄露：** 在 MCP 授权页面立即撤销或删除，再给可信客户端重新创建。
